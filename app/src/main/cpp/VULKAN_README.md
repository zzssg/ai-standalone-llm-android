Vulkan shader generation for ggml (Android)

Why this is needed
- The ggml Vulkan backend embeds precompiled shader sources (C++/header) generated by a host tool
  called `vulkan-shaders-gen`. When cross-compiling for Android, the generator must be run on the host
  (Windows/macOS/Linux) and the produced files must be available to the Android build.

Quick steps (host machine, not on device)
1. Build the shader generator on your host machine.
   - Open a terminal in:
     `app/src/main/cpp/lib/llama.cpp/ggml/src/ggml-vulkan/vulkan-shaders`
   - Create a build directory and run cmake for a native host build (example using MinGW/MSYS2 or a Linux/macOS shell):
     - Linux/macOS:
       ```bash
       mkdir build-host && cd build-host
       cmake .. -Bbuild -DCMAKE_BUILD_TYPE=Release
       cmake --build . --config Release
       ```
     - Windows with MSYS2/MinGW, adapt command-line to your environment.

2. Run the generated tool to produce headers
   - The tool binary `vulkan-shaders-gen` will be built inside the build dir.
   - Run it and point output to a temporary directory, e.g.:
     ```bash
     ./vulkan-shaders-gen --out-dir ./out-shaders
     ```
   - The run will produce `ggml-vulkan-shaders.hpp` and `ggml-vulkan-shaders.cpp` (or similar files).

3. Copy generated files into the Android build tree
   - Copy the generated files into the ggml CMake binary dir expected by the Android build, or into the repo so CMake picks them up. A safe place is:
     `app/src/main/cpp/lib/llama.cpp/ggml/src/ggml-vulkan/` (or the `CMAKE_CURRENT_BINARY_DIR` used by ggml when building).
   - Example:
     ```bash
     cp out-shaders/ggml-vulkan-shaders.hpp ../../../
     cp out-shaders/ggml-vulkan-shaders.cpp ../../../
     ```
   - Alternatively, run the host generator and place the generated files at:
     `app/src/main/cpp/lib/llama.cpp/ggml/src/ggml-vulkan/` so they end up embedded in the Android build.

4. Build the Android project (Release/arm64)
   - From project root (Windows PowerShell):
     ```powershell
     .\gradlew.bat clean
     .\gradlew.bat assembleDebug
     ```
   - Prefer building `arm64-v8a` (64-bit) for performance.

Notes and tips
- If you prefer not to add generated sources to the repo, you can add a copy step in your CI that runs the host build and copies the files into the Android project's `CMAKE_CURRENT_BINARY_DIR` before the native build.
- Some Android GPUs/drivers work better with Vulkan, others with OpenCL. If Vulkan fails, try enabling OpenCL (`GGML_OPENCL`) and the Adreno kernels flag.
- For development speed, start with CPU-only builds and only enable Vulkan after you successfully generate and integrate the shader files.
- If you run into linker issues for Vulkan on Android, ensure your NDK and CPU/ABI target match (arm64-v8a recommended) and that the device supports Vulkan 1.1+.

Automated Gradle integration
---------------------------
This project includes Gradle tasks that will attempt to build the host `vulkan-shaders-gen` and copy the generated files automatically before the Android native build runs.

- To use the automation, simply run:

  Windows PowerShell / macOS / Linux:

  ```powershell
  .\gradlew.bat assembleDebug
  # or
  .\gradlew.bat assembleRelease
  ```

- Gradle tasks created:
  - `buildVulkanShadersHost` — builds the host `vulkan-shaders-gen` tool using CMake.
  - `copyVulkanShaders` — copies `ggml-vulkan-shaders.*` from the host build output into `ggml/src/ggml-vulkan`.
  - `preBuild` depends on `copyVulkanShaders`, so the shader generation will run automatically prior to native compilation.

Notes:
- The host build requires a working CMake and a native toolchain on your host system. On Windows you'll need either a MSYS2/MinGW environment or CMake + Visual Studio toolchain that can build the small host binary. On Linux/macOS a default CMake+gcc/clang toolchain should work.
- If you use WSL on Windows, run the Gradle build from WSL or adapt the PATH so that cmake is available in your shell. The Gradle task tries to detect Windows vs Unix and runs commands accordingly but the host environment must have CMake and a native compiler.
